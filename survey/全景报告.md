## 3. 综合洞察(消化所有调研后的 5 条结论)

### 3.1 "场景的本质 = 5 维空间,不是 persona"
RealMem 11 场景全堆在 `I={对话}, S=个人, V=first-person` 一个角落 → 我们采的是整个 5 维空间。这条**消解了"为什么是 11 不是 12"的死亡问题**,且形式化定义场景。

```
Scenario = (I, S, V, T, O)
  I (IngestChannels)   ⊥  S (MemorySubject)
  V (Perspective)      ⊥  T (TemporalDynamics)
  O (MemoryOpsProfile)
```

### 3.2 "verifier 命门已解一半,另一半正是 novelty 卖点"
- ✅ **forgetting**:FAMA = `max(0, MPA - λ·(1-FAA))`,直接对接 `MemoryAtom.status`(current/outdated)
- ✅ **TOFU Truth Ratio** 给"模型偏向 outdated 多深"的连续信号
- ✅ **conflict**:Knowledge Conflicts Survey 给了 CM/IC/IM 三类型 taxonomy
- ❌ **conflict 维度自动判分公式无标准** → 我们造(§4 verifier_conflict 伪代码)
- ❌ **consolidation 维度完全无公式** → 我们造(§4 verifier_consolidation 伪代码)— **这是 SIGMOD 卖点最硬的一块**
- ✅ **attribution**:AutoAIS 公式(NLI-based)+ Diagnosing R/U 的存/取/用归因方法

### 3.3 "数据合成 24-26 的 3 大跃迁要全踩"
| 旧 (2024) | 新 (2025-2026) | 我们的踩点 |
|---|---|---|
| 扩 prompt(数量/难度) | **控分布**(声明式 + 正交维度 + 采样概率) | 5 维场景抽象 + DataMorgana 配置式 |
| 答案数据 | **推理轨迹 + verifier**(可机器判分) | 4 个 verifier + LLM-judge 3 投票 |
| 单 prompt 链 | **multi-agent 编织** | LangGraph + 4 agent(User/Env/Adversary/MemChecker) |

### 3.4 "BARE 提醒:Instruct 模型 RLHF 抹掉了分布尾巴"
**蓝海维度(冲突/遗忘)恰是被 alignment 拍平的那片** —— 这解释了 v1 为什么 AI 味重。**对策**:
- step2 不能纯靠 GPT-5 / Claude 出 corpus 一气呵成
- 走"base 发散 + instruct 精修"两段式(用 chat-API 模拟:多样化 few-shot + 显式反 mode prompt)
- few-shot 故意放极端/有缺陷示例

### 3.5 "DRBench 是最接近我们的范式"
DRBench `(C, Q, ℐ, Files)` 四元组、5 阶段合成 pipeline、distractor 注入、异构 ingest(PDF/DOCX/邮件/Mattermost)—— 我们做的是**把它移植到 memory**:
- `ℐ` → 记忆图(带 update/conflict/forgotten/consolidates)
- `Files` → 按 ingest 通道分桶的异构 corpus
- `C` → 评测视角 + 记忆主体
- + **multi-session 时间动力学**(DRBench 缺这环)
- + **多视角同 corpus**(DRBench 缺这环,我们 V 维度的核心)

## 4. 危险竞品全景对比 + 我们的空位

| # | 竞品 | 它做了什么 | 我们的差异(novelty 抓手) |
|---|---|---|---|
| 1 | **Memora**(2604.20006,**最新发现**)| Persona+Sessions+Memory Trace+FAMA;**架构几乎和我们一样** | **它只做单用户对话**(10 persona × preference/activity/goal)。我们 cross-modality(会议/邮件/工单)+ 5 维空间 + 多视角 |
| 2 | RealMem(2601.06966) | 11 个人工设计场景,合成对话 | 全 single-user dialogue,无 scenario schema,无"如何加第 12 个" |
| 3 | Episodic Memory Bench(ICLR'25) | 程序化生成 11 个情景记忆数据集 | 只情景记忆/预设配置/不吃 few-shot/不跨场景 |
| 4 | DRBench(2510.00172) | 100 deep research tasks,5 阶段合成,异构 ingest | **做 deep research 不是 memory**,无 multi-session 时间动力学,无多视角 |
| 5 | MemoryAgentBench(2507.05257,ICLR'26)| 4 能力轴(检索/TTL/长程/选择性遗忘)+ 重构现有集 | **它是 evaluator,不是 generator**;我们是它的上游 |
| 6 | EvoMemBench(2605.18421) | knowledge×execution×in-episode×cross-episode 四象限评 15 种 memory 方法 | 同上,evaluator 不 generator;**我们让 4 象限可生成** |
| 7 | AutoBencher(ICLR'25) | declarative 通用 benchmark 生成器 | 无 memory 概念,无多 session / 演化 / 遗忘 |
| 8 | DataMorgana(2501.12789) | 声明式可控分布的 RAG QA 生成 | 单轮 QA,无 memory dynamics,无 cross-modality |

**我们的精确空位**(三件事交集):
1. **few-shot + 任意场景泛化**(别人都是预设 N 个场景)
2. **覆盖蓝海维度**(conflict / forgetting / consolidation,我们造 verifier)
3. **诊断性归因**(存/取/用/忘 4 步,基于 agent_trace + AutoAIS NLI)

## 5. SIGMOD 一句话定位(基于全部调研 refined)

> **DataMorgana for memory agents: scenario-declarative across 5 dimensions + cross-modality ingest + verifiable memory operators (FAMA + conflict/consolidation/attribution verifiers).**

**贡献三件套**:
1. **5 维场景抽象** `(I, S, V, T, O)`,把 RealMem 等堆在角落的"persona+对话"打开到整个空间
2. **跨模态 ingest 反向生成**(对话/会议/周报/邮件/代码/工单),不再绑死 dialogue
3. **蓝海记忆维度的可机器判分 verifier**(conflict + consolidation 是首个,forgetting 改造 FAMA + Truth Ratio)

**实验三件套**(SIGMOD 必须做):
- **覆盖率图**:5 维空间画出所有现有 benchmark 落点 + 我们覆盖了哪些新格子
- **维度敏感 ablation**:同 corpus 不同 V,题目分数曲线显著不同 → 证明视角变了 benchmark 真的变了
- **冷启动新维度组合**:采全新 `(I,S,V,T,O)` 组合,跑 mem0/Letta/RAG/long-context baseline 看分数差异
- **可信度验证**:我们 benchmark 上的模型排名 vs LongMemEval/MemoryAgentBench 排名 Spearman(目标 ≥0.7)

## 6. v3 设计 · 完整施工蓝图

按 step 列出"技术选型 + 核心公式/代码 + 风险":

### step1 结构层生成
- **输入**:scenario config(5 维)+ few-shot atoms + few-shot questions
- **输出**:`StructuredMemory{persona, atoms[], verifier_criteria{}}`
- **schema 改动**:
  - `MemoryAtom` 加 `source_channel`(meeting/email/...) + `subject_id`(project/customer/...) + `visible_perspectives`(list of V)+ `salience`(0-1)
  - `Question` 加 `op_type`(retrieve/update/conflict/forget/consolidate)+ `presence_criteria`/`forget_criteria`/`conflict_pair`/`consolidated_atom`/`target_atom`
- **prompt 哲学**:不让 LLM "出题又自答",**先造结构 + verifier criteria 再长内容**
- **风险**:LLM 仍可能塌缩到模板 → 用 Persona Hub 风格枚举 + BARE 两段式 + few-shot 反 mode 示例

### step2 multi-agent 编织 ingest corpus
- **底座**:**LangGraph + SqliteSaver checkpointer**
- **4 agent**:
  - **UserAgent**(CAMEL Inception Prompting,严禁出戏,严禁编造 blueprint 外事实)
  - **EnvironmentAgent**(注入 long-range dependency event,需局部 memory stream 防自相矛盾)
  - **AdversaryAgent**(注意:制造 memory 难度,**不是 jailbreak**;TAP 风格 tree search)
  - **MemoryChecker**(每 K 轮介入,4 维评估:一致性/难度/覆盖度/收敛;Meta-Rewarding 防 reward hacking)
- **收敛判定**:CAMEL 5 终止条件 + coverage≥0.9 + difficulty='just_right'
- **关键代码骨架**:已落盘在 `survey/multiagent_synthesis/skeleton_step2_langgraph.py`(75 行,直接基于扩展)
- **风险**:multi-agent token 成本爆 → 用 Phi-4 plurality(N=4)而非更多,MemChecker 用轻量 model

### step3 出题 + 打标签
- **按 `op_type` 分桶**(retrieve / update / conflict / forget / consolidate),配比建议 5:3:2:2:1
- **题目模板**:借 RealMem 4 query type(Static Retrieval / Dynamic Updating / Proactive Alignment / Temporal Reasoning)+ LongMemEval 5 能力 + Memora 3 任务(Remembering/Reasoning/Recommending)
- **关键**:出题时**同步生成 verifier criteria**(presence_criteria 等),不要事后补
- **质量过滤**:Phi-4 plurality voting,N=4 采样,全一致(太易)/全发散(太难)都剔除

### step4 自动判分(verifier 库)
- 4 个 verifier 函数已在 `survey/verifier_metrics/REPORT.md §3.2` 给出完整伪代码:
  - `verifier_retrieve` / `verifier_update`:EM 精确匹配优先
  - `verifier_conflict`:新造,4-tier(good/partial/miss/wrong)
  - `verifier_forgetting`:FAMA 公式 + TOFU Truth Ratio(可选)
  - `verifier_consolidation`:新造,0.5·correctness + 0.3·confidence_match + 0.2·robustness
  - `verifier_attribution`:基于 AutoAIS NLI + agent_trace 存/取/用/忘 4 阶检查
- **统一接口**:`evaluate(question, model_output, gold_atoms, agent_trace, agent_logits) -> VerifierResult`
- **LLM-judge 命门**:3 judge majority(GPT/Claude/Gemini)+ reference-grounded + position swap
- **calibration**:每版抽 50-100 题人工标 + 计算 Cohen's κ ≥ 0.80

### step5 lineage + 可重生成
- **直接走 LangGraph checkpointer**,`thread_id == episode_id`
- 重生成:`graph.aget_state_history(config)` 拿任意 turn 的 snapshot
- 借 Magentic-One 的 **Task Ledger + Progress Ledger** 模式做可读性

## 8. 我推荐的"动手第一刀"

**Phase W1:最小端到端 demo**(选项 A,我之前提的)。理由:

1. **符合你"实验数据是主要"的偏好**——1 周出第一份 FAMA 分数 + verifier diagnostic,可直接看
2. **风险最低**——不一次性赌 5 维抽象,先用 1 个手工场景验证整个 pipeline 跑得通
3. **暴露真问题**——只有跑了才知道 FAMA 的 presence/forget criteria 怎么自动生成、3-judge 投票的成本、long-range dependency 在 multi-agent 编织里能不能稳

**具体起点**(W1 第 1 天):
1. 改 `schema.py`:加 `source_channel` / `subject_id` / `visible_perspectives` / `salience` + Question schema(op_type / presence_criteria / forget_criteria / conflict_pair / consolidated_atom / target_atom)
2. 手工配置一个场景对象:
   ```python
   SCENARIO_PROJECT_HANDOVER = Scenario(
       I=["meeting", "weekly_report", "internal_doc", "email"],
       S="project",  # 项目 P-Falcon
       V="bizline_leader",  # 业务线 leader 视角
       T="project_phase",   # 项目阶段切换
       O={retrieve: 5, update: 3, conflict: 2, forget: 2, consolidate: 1},
       few_shot_atoms=[...],  # 给 micro-example
   )
   ```
3. 改 `step1_structure.py`:把 prompt 改成"生成符合 5 维场景的 atom + verifier criteria"
4. 跑 step1,看新结构层质量(用我们的 audit 视角 + Memora 的 88% human agreement 标准)
