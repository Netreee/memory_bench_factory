## §2 真补丁清单(代码做的 ≠ 注释吹的)

### ★1 `world_gen.build_world` traps 过滤 —— 中文关键词黑名单(最扎眼)
```python
traps = [t.get("trap") for t in (wp.get("traps") or [])
         if t.get("trap") and not any(k in t["trap"] for k in ("近重名","重名","同名","近似名"))][:3]
```
- 正是 `audit_patches.md` 批过的"靠中文子串猜"同款:LLM 写"名字易混 / similar names"就漏过;不跨语言。
- **补丁摞补丁**:同轮已改 `council.traps` prompt 为"不要用近重名/已禁用" → 议会本就不该再产此陷阱,代码再用子串滤一道 = **不信任自己刚改的 prompt**;两道防线都只认"近重名"三个字,换说法一起瞎。

### ★2 `_base_name` —— 注释叫"防表面塌缩",代码只剥三种后缀
```python
s = re.sub(r"[（(][^)）]*[)）]", "", str(name))   # 括号注:张三(数据)→张三
s = re.split(r"[_\-—]", s)[0]                      # 下划线/横线:张三_数据→张三
```
- 只认 `张三(数据)`/`张三_数据`;漏 `张三2`、`张三A`、`张三 数据`(空格)。
- `name_collisions` 兜底用**同一个** `_base_name` → 去重漏的、兜底漏同一批,**等于没兜底**。是"覆盖最常见几种消歧后缀"的启发式,非通用"近似名"判定。

### ★3 `field_kind` 值兜底永远兜不出 person(轻微,诚实降级)
```python
return "number" if _to_num(sample_value) is not None else "text"
```
- schema 没标 `kind` 时人名字段被判 `text` → 疑问词降级"是什么"(非"是谁")。person 正确性**外包给白皮书 schema 质量**,代码自身保证不了。降级安全(不会错成"是多少"),故是局限非 bug。
