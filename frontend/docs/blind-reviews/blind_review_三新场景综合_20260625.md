## 2. 共性强项（三场景一致，可写进论文的底盘）

- **B 视角三场景全 A−**：**0 题面泄漏、~90% 是真记忆题**（强制跨 session 时序/多跳/聚合，单文档答不了），近名/同名实体 + filler 噪声把易题也抬难，**拒答题用"查得到实体、查不到该字段/伪前提"有效封堵 trivial-pass**。→ 这套题**确实在考记忆，不是考检索召回**，是最硬的卖点。
- **接地与时点锚定基本可靠**：survival ≥0.99；agent/kb 周号↔日期↔session 三者自洽（**0 off-by-one**）；多跳末跳、冲突裁决、失效/停统机制在多数场景设计专业。

## 3. ★三条共性病根（跨场景系统性，必须治）

### 病根① 多样性坍缩 —— "换皮不换芯"（C 三场景全 C，**最致命，直击区分度命题**）
三场景的"皮"（domain）确实换了：agent=工具编排、companion=情感陪伴、kb=知识库。**但芯没换**：
- 三者都是**同一套"每实体 ~7 个字段的状态表"**模型；
- 118/114/120 题都坍缩成**"对某实体取/聚合 7 个字段之一"一个母骨架**，只有时间限定词（第N周/截至最新/首次变化）换花样；
- 考点扎堆 3–4 个字段吃 55–88%；表层骨架唯一率虚高（靠人名+周数排列）。

→ **结论：当前"场景区分度"主要来自 domain 词表，不来自"记忆挑战本身"。** 三场景对一个记忆系统的考法近乎同构——这正面挑战了项目的核心假设。**这是本轮最重要的发现。**

### 病根② schema 字段名写进正文（C，渲染层，三场景同族）
- companion：**100%** signal 文档把「字段名」连括号写进正文（"本期「压力水平」为6"）；
- kb：~50% 文档原样列字段名、36.8% 一口气 dump ≥5 字段；正文还混入 `fact_refs` 等内部索引词；
- → 典型"把结构化记录逐字段叙述化"的 AI 合成味，真实文档绝不这样念字段表。**病在渲染 prompt，跨场景复用同一个模板就跨场景同病。**

### 病根③ 判分口径未声明 + 长尾/冲突线薄缺（D，三场景一致，呼应闭环 UNMET）
- **判分口径三场景都没在交付物声明**：carry-forward（未更新即结转）、拒答 sentinel（`None` 已失效 vs `INSUFFICIENT_EVIDENCE` 无据，两套混用）、趋势二分判定 —— 朴素 exact-match grader 会成片误杀好系统。
- **长尾能力线每类 2–5 题**，统计上分不出系统；**冲突线 agent 3 / companion 2 / kb 0**（kb 完全无冲突题），还普遍缺 计数/否定/跨实体比较 —— "全面评测记忆"的高阶维度是空的。这正是闭环 UNMET（L5/L6 配额没凑齐就 fail-open）的产物。

## 5. 复发 bug 追踪

- **off-by-one**（office 历史复发 5 轮）：本批 **companion 单点事实查询整类复发(6/6)**，agent/kb 干净 → **是题型 phrase 模板的时点锚问题，非全局**；凡用"第N周"裸锚的题型都要查。
- **schema 词写进正文**：本批新确认的**跨场景渲染 bug**（companion+kb），是多样性坍缩的渲染层成因。
- **判分口径未声明**：跨场景反复出现，应一次性在 `00_about.json` 固化（拒答/carry-forward/趋势/权威源优先级）。

## 6. 给算法/工程 fork 的修复优先级（审查 lane 转交，非自改）

1. **【P0·治区分度】出题配额层跳出"7 字段单点取值"母题**：每场景注入**结构性不同**的记忆挑战（agent 偏工具链因果/重试归因；companion 偏跨字段联动"压力升时偏好变没变"；kb 偏版本谱系/跨条目依赖），而非同一张表换 domain 词。否则三场景对记忆系统同构 = 区分度证伪。
2. **【P0·渲染】signal 渲染 prompt 去 schema 化**：禁止字段名/索引名进正文，把记录"埋进"评审纪要/邮件/工单/postmortem 等异构文体；砍同义三连渲染。
3. **【P1·判分】`00_about.json` 固化判分口径**：carry-forward + 拒答单一 sentinel + 趋势判定 + 权威源优先级。一处定义、所有场景复用。
4. **【P1·覆盖】长尾/冲突线补到每类 ≥8–10 题**，kb 补冲突题；补计数/否定/跨实体比较。
5. **【P1·各场景 gold】**：companion 修 off-by-one 题型模板 + 重算时序变化点 + 修 evidence；kb 统一准确率量纲 + KB-301 单轨；agent 修 Q001。

## 7. 对"不同场景有没有区分度"的结论

- **domain 层有区分度**（语料读起来确实是三个不同世界，filler/对话/条目体各异）；
- **但记忆能力考点层目前几乎没区分度**——三场景都在考"7 字段状态表的取值/聚合"。
- → 想让"场景区分度"成立为论文卖点，**必须让不同场景考出结构上不同的记忆行为**（病根①P0）。这是当前 pipeline 离"scenario-declarative 元生成器"承诺最大的差距，也是审查 lane 给算法线最重要的一条反馈。

## office 带来的两条关键升级

1. **★★ 统一根因浮现：「结构真值层 vs 渲染叙事层 desync」**——比"换皮不换芯"更底层的工程病。三处已亲核坐实同一机理：
   - **office 多跳**：gt 取"结构层/第1周部门负责人"，但叙事层每周换负责人 → hop1 失真，末跳串到 dead-end/旧头（Q015/016/017/019 约 40% 坏）。
   - **assistant 排序**：gt 的"推荐命中率变为X"末跳值是插值的，**不在 world 真值序列里**（刘伟 0.9 不存在）。
   - **kb/assistant 数值率字段**：准确率/命中率 0–1 与 0–100 同实体混用。
   → **病根：`world_state` 机械算出的 gt，与 LLM 渲染出来的 corpus 文本对不上。** 这正动摇"结构先行、gt 可证伪"的护城河——**gt 可证伪的前提是 gt 必须 == 渲染语料所述**。**这是给算法 fork 的最高优先级。**

2. **多跳/冲突的"覆盖"与"质量"是两件事**：office 证明即便把多跳+冲突配额拉满（各 10 题，治了 agent/companion/kb 的覆盖洞），**多跳的质量仍坏（hop1 语义错）**；而**冲突线两份（office 10/10、assistant 9/9）都扎实** → 冲突可推广，多跳要重做。**接地存活 1.0 ≠ 能答**（多跳 gold 全"接地"却不可答）再次坐实。

## 七场景统一结论（不变且更强）

- **强项**：真考记忆（B 普遍 A−/0 泄漏）、冲突线（office/assistant 做对）、周号锚定（除 companion 外干净）。
