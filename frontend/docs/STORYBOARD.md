# Memory Forge

不同场景，对“记住”的要求不同。Memory Forge 根据一个垂直场景和一份示例文档，构建世界及其专属 Memory benchmark。它沿预先定义的 Memory 能力维度组织问题、标准答案与证据，也把每次评测整理成下一版可以继续验证的方向。

1. **每个世界都有自己的考法。**
2. **每次评测，都能为下一版 Memory 给出方向。**

画面内容仅作示意。全片控制在约两分钟以内，实际剪辑可以随旁白和素材自然浮动。

### 成果展示：把一次评测变成下一版的方向

这一段的主角是一张不断成形的“下一轮验证清单”。它要让观众亲眼看见，一次评测最后为版本评审提供了什么。镜头 17–20 的 Office 个案常驻小字：`HISTORICAL INTERNAL RUN · AUDITED CASE RECONSTRUCTION`。

| # | 大约时长 | 画面与动作 | 旁白 | 剪辑 / 声音 |
|---|---:|---|---|---|
| 17 | 约 4 秒 | Q099 的问题、证据和 `MISS` 一起缩小，落入一张按 Memory 能力划分的题目图；Q099 回到自己的能力切片。 | **一道题的结果，会落回整张能力图。** | 镜头持续拉远；Q099 保持橙色，其余格子只作中性背景。 |
| 18 | 约 5 秒 | Q099 所属的“跨时间关系”切片被橙色轮廓圈出；其他切片保持中性，不显示强弱、通过率或排名。 | **它让团队看见：这道失分属于哪类能力，下一轮该先验证哪里。** | 只展示能力归类，不把它包装成内部根因。 |
| 19 | 约 6 秒 | 能力切片折叠成一张大号 `给下一版的验证清单`，小字标明 `VERSION REVIEW INPUT`。三行依次出现：`优先验证：跨时间的关系连接`、`回归检查：当前通过项`、`复验方式：新历史中的同类问题`。 | **下一轮先验证什么、哪些结果要做回归、改后怎样复验，都有了依据。** | 三行各有一次落点；最后让整张卡完整停留。 |
| 20 | 约 5 秒 | 验证清单跨过清晰边界，交给蓝灰色的 `MEMORY 团队`；旁边出现 `候选版本 · 尚未验证`。随后 `下一次验证 · 尚未运行` 落入测试区，不展示通过结果。 | **方向交给 Memory 团队。新的候选，仍要回到新的测试里。** | 常驻 `WORKFLOW ILLUSTRATION`；不演自动改代码、自动升级或已经通过。 |

### 六个世界，六种方向

每个场景先全屏出现，再缩入六宫格。缩进去以后视频继续轻微播放，同时留下一张橙色“待验证问题”签。六镜常驻小字：`MEMORY REQUIREMENT · ILLUSTRATION`。

| # | 大约时长 | 画面与动作 | 旁白 | 剪辑 / 声音 |
|---|---:|---|---|---|
| 21 | 约 3 秒 | 游戏：关键选择留在左侧，后续阵营或任务节点仍是暗色问号；缩入第一格，方向签写 `选择 → 后果`。 | **要检查，选择有没有留下后果。** | 停在“等待验证”的节点，不演候选系统已经做对。 |
| 22 | 约 3 秒 | 长任务 Agent：工具失败亮起，下一步计划卡仍未翻开；缩入第二格，方向签写 `失败 → 新路径`。 | **失败以后，下一步有没有改变。** | 与上一镜使用相同缩放轨迹。 |
| 23 | 约 3 秒 | 客服：承诺与截止时间并排，最终工单状态仍被遮住；缩入第三格，方向签写 `承诺 → 兑现`。 | **说过的承诺，有没有兑现。** | 消息音与画面缩入卡点对齐。 |
| 24 | 约 3 秒 | 陪伴：用户刚更新“只倾听、暂不建议”，Agent 的下一条回复仍为空；缩入第四格，方向签写 `新边界`。 | **刚刚更新的边界，有没有被尊重。** | 复用客服聊天模板，切换文案与色彩。 |
| 25 | 约 3 秒 | 个人助理：新预算或过敏约束亮起，旧推荐留在一旁等待判定；缩入第五格，方向签写 `新约束`。 | **新的约束，有没有真正生效。** | 新约束点亮，推荐卡保持待检查状态。 |
| 26 | 约 3 秒 | 知识库：V2 与 V3 并排，回答槽仍为空；缩入第六格，方向签写 `当前版本`。 | **它能不能分清，什么已经过期。** | 六宫格完成后整体停留片刻。 |
