# 我们的方法 · 当前进展(组会走查)

> 听众:导师(资深、不知细节)+ 学妹(将接手)。本文从零讲清"我们怎么造题",每个内部黑话首次出现给一句大白话。**以代码现状为准**(文档与代码冲突时信代码)。
>
> **一句话定位**:我们造的不是"一套固定的记忆评测题",而是一个**生成器 / 元工厂**——给它【场景描述 + 几篇该领域的真实样例文档(注意:样例里**不带任何题目**)】,它吐出【一整套记忆智能体的评测题库】:每道题有**题面(question)**、**标准答案(gold)**、还有一大堆**语料(corpus)**(让被测系统去"读"的文档堆)。
> - **元工厂**:不是生产零件、而是生产"生产线"——换个场景,它自动配出一套不同的考题。
> - **记忆智能体**:能把读过的东西记住、之后回答相关问题的 AI 系统(我们要测的就是它"记得准不准、会不会用过时信息")。

## 1. 总览:8 段流水线,从场景一路造到出厂题库

整条线是 8 道工序(代码里叫 stage,= 一道工序;每道工序产物逐个落盘成 `00_…06_*.json`,可单独重跑):

```
input → whitepaper → world → orders → well_posed → questions → corpus → grounding
(场景)  (白皮书/议会)  (世界)  (订单)   (边A闸)      (题面)      (语料)    (边B闸)
[人写]   [LLM]         [LLM]   [代码]    [代码]       [LLM]       [LLM大头]  [代码]
```

一句话说清每段在干嘛:
1. **input(场景输入)**:把场景的【描述 + few-shot 文档】写下来。**few-shot** = 给 LLM 看的几个该领域真实样例(周报/病历长什么样),**只示范风格、不含问答**。
2. **whitepaper(白皮书)**:一群 LLM 视角开个"会",读懂这个场景该考哪些记忆能力、有哪些实体字段、文档长什么样,产出一份**白皮书**(= 这次造题的施工蓝图)。这个"会"我们叫**中央议会**(详见 §下文)。
3. **world(世界)**:按白皮书,用代码 + LLM 造出一个**会算账的状态机世界**(§2)——这是整个工厂**唯一的真相源**。
4. **orders(订单)**:每条产线从世界里"**点菜**"——挑出一批"问哪个实体、哪个字段、考哪种能力"的题目规格,并**当场用代码把标准答案算好**。这一批规格就叫**订单(orders)**。(点菜 = 从世界里挑素材出题;订单 = 一道题的结构化规格,答案已烘焙在里面。)
5. **well_posed(边A闸 / 良定义闸)**:出题**前**,纯代码逐张订单复核"这道题的答案是不是世界里**唯一正确**的解"。不合格的当场扔掉(§4)。
6. **questions(题面)**:把过闸的订单交给 LLM **润色成自然语言题面**(代码定题意、LLM 只管措辞)。
7. **corpus(语料)**:把世界渲染成场景化文档堆(信号文档 + 大量无关"草堆"),这是**全流水线最慢、LLM 调用最多的一步**。
8. **grounding(边B闸 / 接地闸)**:出题**后**,纯代码逐题复核"答案能不能在语料里**逐字 + 就近**找到"。找不到的扔掉,剩下的就是**出厂题库**(§4)。

**两道质量闸夹在中间**(边A在出题前、边B在渲染后),合称**验证三角**(§4)。

## 2. 唯一真相源:世界(world)= 一个会算账的状态机

这是整套方法的地基。代码全在 `pipeline/world_state.py`(纯代码、零 LLM、可单测,自检 90+ 项全绿)。

**它长什么样**:世界 = 一堆**实体**(entity,如"AI工程部""某患者"),每个实体有若干**字段**(field,如"负责人""P0缺陷率""血压"),每个 `(实体, 字段)` 配一条**时间线(Timeline)**。时间线 = 一串带时刻的操作(Op):
- 时刻按 **session** 编号(= 第几次,office 场景里就是第几周;每个 session 配一个真实日期)。
- 操作有四种:`SET`(首次设值)、`UPDATE`(改值)、`EXPIRE`(停止统计,值作废)、`DELETE`(删除)。

**为什么非得用状态机**:因为这样代码就能**算出任意时点的真值**——"放电影到第 N 周为止,看当时有效值是多少"。这就给了我们**可证伪的标准答案(gt)**的地基。

- **gt** = ground truth = 标准答案。我们的核心信条:**LLM 负责"好看"(真实的语料),代码负责"正确"(算得出、驳得倒的答案)**。
- **可证伪** = 这个答案是代码机械算出来的、能拿世界重新验一遍,不是"LLM 拍脑袋说对"。这就是我们反复说的**护城河**(= 别人(纯 LLM 出题)抄不走的核心壁垒:代码可算的标准答案)。

**两个哨兵值**(特殊标记,用来表达"无答案"的两种语义,后面 §3 拒答/遗忘要用):
- `INVALID`("__INVALIDATED__"):字段曾经有值、但已被 EXPIRE/DELETE → **该忘了**。
- `INSUFFICIENT`("INSUFFICIENT_EVIDENCE"):字段**从来没出现过** → 拒答(ABS)。

**世界给代码的几个关键查询**(每条产线靠它们算答案):某周当时值、最新有效值、跨周极值(还告诉你极值落在哪周)、首次变更时刻、某时点是否已停用、停用前最后值、所有变更事件按时序排好、沿"软外键"逐跳遍历(§3 L2 用)。还有一个 `stable_query_weeks`:专挑"这一周文档里没复述、但确实有有效值"的周来提问——**逼着被测系统跨周回忆,光看当周文档答不出来**。

> **重要纪律:mention-on-change(变了才说)**。渲染语料时,一个事实**只在它发生变化的那一周写一次**,之后不再复述。这样要回答"第 N 周是多少"就必须跨周回忆,而不是在当周文档里照抄。

## 3. 五条能力产线(逐条:考什么 + 怎么从世界点菜 + gold 怎么用代码算)

**产线(line)** = 一类记忆能力的"车间",代码在 `pipeline/lines/Lx.py`。每条产线是同一个基类的子类,自带一套"**六件套**"方法(穿过多道工序):
- `prepare` — 在 world 工序往共享世界里**叠本线需要的额外基质**(基质 = 出这种题所需的世界素材);默认啥也不做。
- `feasible` — 先问一句"当前世界喂得饱这条线吗",喂不饱就跳过(避免默默产 0 题)。
- `enumerate` — 在 orders 工序**点菜**:挑题目规格 + 当场烘焙 gold。
- `gt` — **护城河**:给一道订单,用代码**重新算**答案(自检里有"重算 == 烘焙"的断言,证明答案确实代码可复现)。
- `intent` — 在 questions 工序给出"提问意图 + 哪些词必须从题面藏掉"。
- `well_posed` / `ground` — 边A闸 / 边B闸的本线判定(§4)。

> 加一条新线 = 新写一个 `Lx.py` 文件 + 注册表加一行,别处不动(这正是"产线即插件"的设计收益)。

**共享同一个世界**:所有产线读同一个状态机(这叫**命门1**:防止各产线各造各的世界、语料自相矛盾)。(命门 = 全系统成败的关键卡点;命门1=共享世界防矛盾,命门2=每线自带代码gt,命门3=接地闸。)

下面逐条过(现状:**L1/L2/L3/L5 已建成且自检全绿;L4 刚建成、自检绿**):

### L1 时间线(`L1_timeline`)— 最基础的"记得准不准"
- **考什么**:一条多能力捆绑线,7 种子能力:
  - **IE**(某周当时值):"第 N 周那会儿,X 的负责人是谁?"(故意问中间某周、不是最新值,考"别拿最新值糊弄过去的事")。
  - **KU**(最新值):"截至最新,X 的负责人是谁?"
  - **TR**(首次变更):"X 的负责人是哪一周第一次换的?"
  - **MR**(跨周极值):"全程里 X 的 Oncall 数最高 / 最低是多少?"
  - **FORGET**(遗忘/停用):问一个已经停止统计的字段,期望系统答"已停止统计",而不是报个旧值。
  - **PREEXPIRE**(停用前值):"那个已经停掉的指标,停之前最后一次是多少?"
  - **ABS**(拒答):问一个**本场景根本不存在**的字段,期望系统答"查无此记录"。
- **怎么点菜**:遍历世界每个 `(实体, 字段)`,按能力挑合格的提问点(如 IE 专挑"非最新的中间值",KU 专挑"最后一次变更后的稳定周")。各能力按一张权重表 `_CAP_WEIGHT` 分配配额。
- **gold 怎么算 = 护城河**:直接调世界的 `gt_ie/gt_ku/gt_mr/...`。MR 还会返回"极值落在哪周",方便后面接地。

### L2 关系多跳(`L2_relational`)— "拐弯"的推理
- **考什么**:跨实体 N 跳。例:"负责 X 部门的**那个人**,**他**向谁汇报?"——给起点(X 部门)和关系链(负责人 → 汇报对象),但**不给中间那个人**,逼系统跨文档把链接起来。
- **怎么造基质(prepare)**:把"人名类字段"的值**提升成独立的人员实体**,再给人员配一个"下一跳字段"(汇报对象),这样 `部门.负责人=张三` → 去查名为"张三"的实体的"汇报对象"。这种"**字段的值正好是另一个实体的名**"= 一条边,我们叫**软外键**(soft foreign key;借数据库"外键"的概念,但没有硬约束、靠代码保证引用完整)。下一跳值用**真实人名**(不写死 CTO/CEO 头衔)——这是为了①域无关(医疗场景就是医生名)②消除别名漂移(答案是名、语料也渲名)。
- **gold 怎么算 = 护城河**:`gt_multihop` 沿软外键在**指定那一周**逐跳取状态机切片值,末跳值 = 答案;断链 → INSUFFICIENT。关系会随周变(换了负责人、汇报关系跟着变),所以答案随"问哪一周"而变。
- **桥实体**(bridge,= 链中间那个人)**必须从题面藏掉**(`hide` 列表),否则系统单文档就能抄近路、不算真多跳。

### L3 过程排序(`L3_process`)— "谁先谁后"
- **考什么**:给一组散落在各文档里的变更事件(打乱呈现、不给日期),让系统按**真实发生先后**排序。与 L1 正交(L1 问"某点的值",L3 问"这些变更的先后")。
- **怎么点菜**:基质免费(状态机里每个 UPDATE/EXPIRE 本身就是一个事件)。每个实体取 ≥3 个**跨字段、跨周**的事件。**关键源头修复**:剔除"复现值"——同一个 `(字段, 值)` 在世界里出现过不止一次的事件不要(否则"某字段变为该值"指代不唯一,无法定位是哪一周)。
- **gold 怎么算 = 护城河**:`gt_event_order` 从世界**重新**把选中的事件按 `(日期, session)` 排好。出题时**故意按字段名(非时序)呈现**,日期全藏掉——否则正确顺序就直接喂给系统了。
- **评分**:排序题不能用精确匹配,用 **Kendall-τ**(肯德尔等级相关系数,衡量两个排序有多接近)。

### L4 偏好隐式(`L4_preference`)— "从行为反推它的偏好"(刚建成)
- **考什么**:从【散落各周的选择行为】反推那个**从未明说**的稳定偏好。**签名设计**:故意让"偏好(= 出现最多的那种,即**众数**)≠ 最近一次的选择"——这样答"最近一次"(recency,只看最近)就会错,逼系统跨文档聚合。
  - **众数**(mode)= 一组数据里出现次数最多的那个值。
- **怎么造基质(prepare)**:从白皮书拿到"偏好轴"(如"周会形式 ∈ {线上, 线下, 混合}"),用代码确定性地给主体实体编一串**有偏的选择流**(偏好项占比 ≈60%、保证唯一众数 + 领先亚军够多 + **末位故意 ≠ 众数**抗 recency)。**源头只产良定义题**,闸只兜底。
- **gold 怎么算 = 护城河**:`_mode` 复算众数,与烘焙相等。
- **现状**:产线自检绿,但**白皮书议会暂未稳定产出"偏好轴"**,所以端到端跑通还差议会那一环喂料。

### L5 跨来源冲突(`L5_conflict`)— "官方说 vs 传闻说,信谁"
- **考什么**:**同一时刻**、两个来源对同一事实各执一词(一份官方通报、一份小道传闻),问到底认定哪个。和 L1"历史上出现过不同值"(那是合法演化、不是矛盾)划清界限。
- **怎么造基质(prepare)**:给"有权威值的文本类字段",在那一周追加一条**低可信"小道"值**,存进**侧信道** `ws.conflicts`。
  - **侧信道**(side channel)= 单独开的一块存储,不写回主时间线 → **canonical(权威/官方真值)时间线一动不动**,所以 L1/L2/L3 的 gold 不被污染(这是命门1)。
  - 小道错误值 = 同字段**别的实体**用过的真实取值("张冠李戴",看着合理而非瞎编),且**绝不能是本实体自己别周的真值**(否则那其实是合法历史、矛盾退化,见 §4 坏题例)。
- **gold 怎么算 = 护城河**:按裁决规则 `source_reliability`(信来源可靠度高的)→ gold = 权威值。小道值由渲染器另吐一篇低可信文档,与权威文档同周并存 → **语料里真的出现矛盾**。
- **区分度**:朴素检索只取更扎眼/更高频那条(常是小道)→ 答错;只有"检索两边 + 按来源裁决"的系统才对。

## 4. 两道质量闸(验证三角):一道好题 = 题面、答案、语料三边一致

**验证三角**(论文核心框架):一道好题 =(题面 question, 答案 gold, 语料 corpus)三者一致,需要三道独立的闸:**(A) 良定义、(B) 接地、(C) 可答性**。实测教训:**(B) 替不了 (A)**——接地闸把"值在不在语料"治到 86%,但剩下的错 100% 落在 (A)。目前 **(A)(B) 已落地代码,(C) 仍是设计**。

### 边A · 良定义闸(well_posed)— 出题前,纯代码,不碰语料
- **一句话**:**良定义** = "这道题的答案是它在**世界里唯一、合法、可复算**的正确解吗?"把题面承诺的坐标(考哪种能力、问哪一周/哪种聚合)代回世界机械重算,得到的答案必须存在、唯一、类型对、且和烘焙的 gold 逐字段相等。
- **怎么跑**:`pipeline/well_posed.py` 逐张订单派到各线的 `well_posed()`,过闸子集**覆写 03_orders**(只让良定义题去出题、不浪费 LLM),弃因逐条留报告。基类默认放行(opt-in 收紧),已建线各自覆写。
- **它拦住的真实坏题(举例)**:
  - **L1 Q19(算错/陈旧的极值)**:某订单 MR 极值 gold 烘焙成"0.14",但代码拿世界重算 = 该实体最高只到"0.13"。W1 重算闸当场抓出"重算≠烘焙",drop。
  - **L1 Q07(答案类型错配)**:问"管理跨度是多少"(该答数字),gold 却是个人名。W3 类型闸抓"问数答人名",drop。
  - **L2 无周锚 → 多解**:一道时变关系链题题面没点明"第几周"。因为关系逐周变、"向谁汇报"逐周多值、gold 不唯一 → INV-1 闸 drop("无周锚")。
- **一个重要工程教训**:我们删过几道"看着合理、实测却**误杀好题**"的检查(代码注释里叫**撤下代理**——"代理"指用一个**相关症状**冒充真病因的检查)。例如 L2 的 `roles_of≥2`(一个人有多重身份就判歧义)实测 13% 误杀 / 0 真覆盖;L1 的 W5(极值平手判歧义)实测 10.3% 误杀——因为题面问"值"不问"哪周",平手时值仍唯一。**"连接度 / 平手"是相关症状、不是"答案不唯一"的真因**,故撤下。

### 边B · 接地闸(grounding)— 渲染后,纯代码,不碰世界
- **一句话**:**接地**(grounding)= "这道题的答案能在它的**证据文档**里**逐字 + 就近**找到吗?"找不到就**不出厂**。
  - **接地** = 让"源自世界的答案"落在"渲染出的语料"里、踩到实地;不接地 = 答案在语料里悬空。
  - **病根**:世界生了两个独立的孩子——订单(gold)和语料(corpus)都从世界各长各的、**全程不照面**,LLM 渲染一跑偏,gold 就在语料里失真。接地闸就是把这两支**汇合**做交叉校验(命门3)。
- **判定原语 `attributed`**:答案值与"锚名"(实体名/桥实体)要在某篇证据文档的 **±90 字符**窗口内共现(都归一化后做子串)。(窗口从 ±50 放宽到 ±90:±50 把"相距 68 字的真归属"误杀了。)
- **怎么跑**:`pipeline/grounding.py` 逐题派到各线 `ground()`,**fail-closed**(没 ground()/抛异常 → 一律弃)。出厂 = `06_grounded_questions.json`,并算出**存活率**(survival = 接地通过数 / 总数,按线/按能力都有)——这个数后面闭环要当除数用。
- **它拦住的真实坏题(早期 office 实证)**:
  - **① 幽灵值**:某排序题 gold 引用"尤娜/沈婷",全 10 万字语料精确检索 **0 次**(压根没渲进去)。
  - **② 串部门**:"基础架构部 P0 最高"gold=0.14,但语料里它最高 0.13;0.14 其实是隔壁数据安全部的值(答案挂错了实体)。
  - **③ 别名不匹配**:某人语料里只渲成"刘总/CPO"、从不渲成"CEO",而 gold=CEO → 读对语料的系统反被判错(这类治本在上游:让汇报对象建模成真人名,见 L2)。

> 两闸**正交、串联**才是完整护城河:边A 管"题成不成立",边B 管"答案落没落到语料里"。

## 5. 闭环旋钮:从"给 token、题数随缘"到"设目标题数、管够为止"

**病灶**:整个工厂原本只有一个有效旋钮 `target_tokens`(目标语料字数),但它只灌**草堆**(haystack,= 用来淹没信号的无关填充文档),碰不到信号(题目本体)。你真正想拧的"出多少题、各线配比、难度分布",要么不存在、要么"议会算了执行端不读"。**旋钮的定义 = ① 能设 ② 被执行**,原来两条都不满足。

**解法**:把工厂从 **open-loop(给 token、题数随缘)** 升成 **closed-loop(给目标 floor、管够为止)**。代码在 `pipeline/closed_loop.py` + `pipeline/targetspec.py`(v0 已落地,离线自检 23/23)。给了 `--min-questions N` 就走这条路径:
1. **反推世界规模**(`invert_rate`):用**保守的存活率先验** + 余量(slack=1.4),从"要多少题"反推"需要多大世界(实体数/周数/各线配额)",并夹在合理区间(实体 8–80、周 6–26)防反推出几百实体。**存活率当除数**(要 30 题、存活率 0.5,就得供 60 单)——这个除数正是边B闸现成产出的数,白捡。
2. **① 供给环(便宜、不渲染)**:world → orders → 边A闸,数一下各线产够配额没。差得多(超 15% 容差)才长世界重跑;小缺口交给余量。
3. **出题 → 整轮渲染(贵)→ 接地**。
4. **② 纠偏环**:数最终题数够不够 floor。够 → 标 MET 返回;不够且是"可行线没产够"→ 用**实测存活率**重新反推、长世界再来一轮(有界 max_rounds);不够且是"基质天生供不出的线"→ 别空转,直接 fail-open。
- **fail-open**(失败也放行)= 轮次耗尽仍不达标,**题库照出 + manifest 标 UNMET 留痕**,绝不为凑数塞坏题(坏题始终被两闸挡着)。

**两个配套机制(一句话带过)**:
- **None 作答协议**(`ANSWER_PROTOCOL`):题库出厂显式声明 None 的两类语义——"从未存在"(ABS → 答"查无此记录")vs"曾有已停"(FORGET → 答"已停止统计"),让 eval 侧把哨兵映射到人类作答,治"None 没定义→理性系统被误判"。
- **增量重渲**:②环长世界时只渲**新增实体**、旧文档原样保留(把成本从"整套语料"降到"新增那点"),靠 `augment`(只长新实体的世界)+ `render_only`(只渲指定实体)两个干净原语,不用"哪周渲过了"的补丁式特判。

## 6. 怎么跑 / 怎么验

- **各产线 + 基建自检**(纯代码、零 LLM、秒级):
  - `python -m pipeline.lines` — 产线注册表 + 依赖图 + 可行性闸自检。
  - 各线单测:`python -m pipeline.lines.L1_timeline`(及 L2/L3/L4/L5)、`python -m pipeline.world_state`、`python -m pipeline.grounding`、`python -m pipeline.well_posed`、`python -m pipeline.targetspec`。
- **真车出题**:
  - `python -m pipeline.factory --scenario office --target-mtokens 1.0` — 普通跑(给 token,题数随缘)。
  - `python -m pipeline.factory --min-questions 80 --per-line L2_relational=15` — **闭环旋钮**(设目标题数 + 各线 floor,管够为止)。
  - `python -m pipeline.factory --scenario office --to world` — 只跑到世界(调议会/世界生成用);`--only questions --run <id> --force` 单独重跑某步。
  - `python -m pipeline.factory --list-runs` — 列出所有 run。
- **看产物**:每个 run 一个目录 `output/runs/<run_id>/`,里面 `manifest.json`(单一真相:各 stage 状态 + 算法元数据 active_lines/entities/sessions/orders_by_line/well_posed/grounding/met_status/diversity)、`run.log`、`prompts.jsonl`(每次 LLM 调用留痕,带延迟)、`00_…06_*.json` 逐 stage 产物 + 两份闸报告。
