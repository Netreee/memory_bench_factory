## 〇、一句话 + 背景(2 分钟)
- **一句话**:我们做的不是【一套固定的记忆评测题】,而是一台【**造记忆评测题的机器**(生成器/元工厂)】——给它一个场景描述 + 几篇示例文档(没有问答),它吐出一整套记忆智能体(memory agent,= 带长期记忆的 LLM 系统)的评测题库(题目 + 标准答案 + 配套语料)。
- **为什么要做**(动机,讲给导师):
  1. 记忆智能体火了,但**怎么评**没解决——现有记忆 benchmark(LoCoMo / LongMemEval / MemoryAgentBench…)几乎都是【固定数据集】:人工标注贵、场景单一(基本都是"单用户对话")、换个领域就得重造。
  2. 我们换个层次:**不造数据集,造"造数据集的机器"**——给新场景能现造、答案由代码算(不靠人也不靠 LLM 判),区分度是【设计出来的】不是【碰运气】。
  3. 类比:别人手画一张张考卷;我们造一台**印考卷的机器**,而且**标准答案是机器算出来的、连出题的 LLM 自己都不知道**(防泄漏/防作弊)。

## 二、★理念与经验(这是我们最硬的东西,值得多讲)

> 这套方法论是【5 波独立盲审 + 反复踩坑】打出来的,不是设计出来的。详细账见 `pitfalls_4lines.md`(论文"挑战与教训"的底稿)。

**1. 端到端生成 + 独立盲审闭环(我们的"实验范式")**
- 不是写完代码就信。每造一版,派【4 个互不通气、不知道产物怎么来的盲审 agent】只拿脱敏成品(打乱的题+答案+语料)挑错。
- 走了 **5 波**(v3→…→020444),综合评级 C-→B-/B。**这个闭环本身是方法贡献**:让"质量"可被独立证伪,而不是自我感觉良好。
- 比喻:自己改的卷子永远觉得没问题;找几个不知情的人盲做盲判,才看得见真错。

**2. ★对"补丁式/打地鼠式修复"零容忍(我们最痛的教训)**
- 同一个 bug(周编号 off-by-one)**我"修好"了 3 次才真死**;每次自检都绿、下一波盲审都复发。
- 根因:① **自检全绿 ≠ bug 死了**——自检没覆盖"真实消费者路径"(下游导出/评分/LLM 渲染读的是另一个字段);② 每次都修在【我以为的出错点】,真实读取在【别处】。
- 立的规矩(讲给学妹,这是接手第一课):
  - **fix 不算完,直到下一波独立盲审盖章**(不是自检绿就算)。
  - **从源头消歧**,别追着下游打补丁(让标准答案"出厂即唯一人类口径",而非留个内部表示让下游猜)。
  - **"看着像规则"≠"是规则"**:我们删过 3 条"形式上合格(查世界、不含硬编码)却误杀 10–16% 好题、零真覆盖"的伪规则——上线前必须拿真实数据量【误杀率/真覆盖率】。
  - **诚实**:我自己也打过一次补丁(中文关键词黑名单),被独立代码审计当场抓出——**反补丁不能自评,要交给只看代码的审计**。

**3. 验证三角(我们的统一框架,论文的核心概念之一)**
- 一道好题 = 题面 / 答案 / 语料【三者一致】,且都源自同一个世界。三条边各需一道独立的闸:
  - **边B 接地**:答案能不能在语料里逐字找到?(已建)
  - **边A 良定义**:答案是不是该题面在世界里的【唯一正确解】?(已建)
  - **边C 可答性**:只读语料能不能答出来?(★还没建,见下一步)
- 关键洞察:**三条边正交,谁也替不了谁**。我们一度把"接地存活率"刷到 100% 还沾沾自喜,盲审分却不升——因为错全在另外两条边(接地只管"值在不在语料",管不到周号/类型/多样性)。**单一硬指标会骗人**。

**4. 代码可证伪的标准答案 = 护城河(不靠 LLM 判分)**
- 世界是个【会算账的状态机】,答案由代码从世界机械算出(LLM 全程不碰答案)。所以答案【可重算、可证伪、不会被 LLM 的幻觉污染】。这是和"用 LLM 当裁判(LLM-as-judge,有已知偏见)"的根本区别。

**5. 跨场景泛化(贯穿的纪律)**
- **域知识只从白皮书来**,代码/prompt 里绝不写死领域词(写死过 CTO/CEO、用中文子串猜字段,都翻过车)。判据:"换到医疗场景还成立吗?" 这保证这台机器能服务任意场景,不是只会做"公司周报"。

**6. 多样性是一等公民**(但还没解决,见下一步)——我们程序化测语料多样性(NDG/IDO 等),并已意识到"维护一个 prompt 停用词库不现实(跨场景失效)",真正的根在【世界生成得更丰富】。

## 三、★悬置的重要工作(= 学妹的下一步;我补了几个你可能没列的)

> 现状坐标:5 条产线已建(L1/L2/L3/L4/L5)、两道闸已建、闭环旋钮已建、None 作答协议 + 增量重渲刚做完。下面是【重要但还没做】的,按价值排。

**A. 剩余产线(taxonomy L1–L7,还差 2 条半)**
- **L4 偏好隐式**:产线代码已建 + 自检绿,但【议会暂不稳定产出"偏好轴"】→ 端到端还差"喂料"这一环(office 场景本身没有"每周重复选择"维度,需要带选择维度的场景如医疗"随访方式"才激活)。**收尾点**:让中央议会稳定识别/产出偏好轴 + 跑一个有该维度的场景验证。
- **L6 拒答边界**:知道记忆边界、不存在就拒答。**连设计都还没做**。
- **L7 巩固摘要**:长跨度要点/趋势回忆(非逐字)。**连设计都还没做**(且调研发现:巩固类【没有现成标准指标】,verifier 得我们自己造——novelty 高)。

**B. 难度问题(可控难度)**
- 现状:难度是"碰出来的",不能【设】(如 3 成易/5 成中/2 成难)也不能【验】。
- 已有完整算法设计(`closed_loop §4`:每线一个 `difficulty_score()` 结构性难度代理 + 切档 + 分层采样),**但未实现**(定为 v1,暂缓)。
- ★诚实边界(讲清):`difficulty_score` 只是【生成侧代理】,"对模型到底难不难"必须靠【多 baseline 实测正确率】校准 → 难度和 D 项(多 baseline 审判)要一起做。

**C. ★多样性问题(主理人最在意、但做法未定)**
- 问题:题型扎堆(汇报对象+排序占 74%)、话题集中、AI 套话注水;但**不是字面复制**(近重复对=0)。
- 已排除的错路:维护 prompt 停用词库(跨场景失效)、末端去重(根本不在复制)。
- **根方向假设(待验证)**:从【世界生成更丰富】动手——世界结构单一→可考的能力/话题就那几种;让世界长出更多样的实体/字段/关系类型,渲染才有真东西可写。需要一个【世界丰富度的可证伪度量】(像难度那样,别"祈祷变丰富")。详 `open_diversity_problem.md`。

**D. ★多 baseline 审判(这台机器的最终目的)**
- benchmark 造出来是【给真实记忆系统打分】的。`eval/multi_system.py` 存在,但只有【很旧的 v3 输出】,**从没在当前题库上重跑过**。
- 这是【验收】:跑多个记忆 baseline(不同记忆架构)→ 看题库能否拉开区分度 + 校准难度。**是论文的实验主体**。

**E. 我补的几个遗漏(你列表里没有、但重要)**
- **边C 可答性闸**(验证三角第三条边):只读语料、模拟读者能否答出。目前只有概念,无设计无实现。**这是"题库是否真能被答"的最后一关**。
- **round2 四宗修复待盲审盖章**:周号/类型/重名/锁周 在生成层已验消失(小跑 181618),**但还没过一波独立盲审确认**——按我们自己的规矩=没算完。
- **跨场景实证**:目前主要在 office 场景打磨,medical 只浅试。要证明"跨场景泛化"得真跑几个不同领域端到端。
- **论文化**:验证三角(框架) + 反打地鼠账(挑战与教训) + 多 baseline(实验)——三块是论文骨架,可以开始攒。

## 四、一页纸总结(答问时指这里)
- **是什么**:记忆 benchmark 生成器,scenario+few-shot → 题库;答案代码算、LLM 不碰。
- **已做**:5 条产线 + 两道闸(接地/良定义)+ 闭环旋钮 + 5 波盲审打磨。
- **方法贡献**:① 元工厂范式(造机器不造数据)② 代码可证伪 gt 护城河 ③ 验证三角 ④ 端到端+独立盲审闭环。
- **下一步(交棒)**:L6/L7 产线 → 难度旋钮 → 多样性(世界更丰富)→ 边C可答性 → **多 baseline 审判(验收+论文实验)**。
- **一句话理念**:对打地鼠零容忍,从源头消歧;单指标会骗人,只信独立盲审。
