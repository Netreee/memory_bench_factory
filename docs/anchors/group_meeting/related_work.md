## §0 一页纸：我们在做什么（先给导师一个锚）

先把三个反复出现的术语说清楚，后面才好讲：

- **记忆智能体（memory agent）**:一个能跨多轮、多次会话"记住"信息的 LLM 系统。它把读到的东西写进一个外部"记忆体"（向量库 / 知识图 / 摘要树），下次提问时再检索回来。代表系统:Mem0、MemGPT、Letta、A-MEM、HippoRAG。
- **记忆评测 benchmark**:一套"喂给记忆智能体一段长历史 + 一批问题 + 标准答案（ground truth, 下称 gt）"的题库，用来量化它到底记没记住、会不会用。
- **我们做的不是又一个 benchmark，而是一个 benchmark 的【生成器 / 元工厂】**:输入 = 一句场景描述 + 几篇该领域真实文档（few-shot，**不含问答**）;输出 = 一整套该场景的记忆评测题库（题面 + 标准答案 + 配套语料）。

**一句话定位**:别人手工造**一个固定数据集**;我们造一台**能为任意场景现造数据集的机器**，且答案由**代码从一个独立状态机机械算出**（LLM 全程不碰答案）——这是护城河。

下面五节分别回答:① 现有记忆 benchmark 的版图与局限;② 评测/验证维度怎么分类（我们的"考什么 + 怎么判"从哪来）;③ 数据合成 / 多智能体范式（我们的"中央议会"从哪来）;④ 规格澄清（我们"白皮书=被执行的合同"从哪来）;⑤ **我们的精确定位**。

## §1 记忆智能体评测的版图：现有 benchmark 各考什么、什么局限

> 我们逐字 clone 真仓 + 抽样 instance 对标了 16+ 个主流记忆 benchmark（落盘 `benchmark_landscape.md`）。可分三代：

**第一代·单用户长程对话（红海）**
- **LoCoMo**（长对话评测，2024）:用 persona + 因果图生成超长多轮对话，人工编辑约 15%，考单跳/多跳/时序/拒答。是"长程对话记忆"的事实标准。**关系**:我们借它的对话媒介形态，但它全是合成对话、人工成本高。
- **LongMemEval**（2024）:把属性受控地埋进 ~500 个会话的"草堆"里，提出 5 类能力（单跳信息抽取 / 多会话推理 / 知识更新 / 时序 / 拒答）。**关系**:它的能力清单直接启发了我们的 L1–L7 坐标系（见 §2、§5）;但它是固定数据集、单一对话媒介。
- **RealMem**（2601.06966）:人工设计 11 个场景（旅行/理财/项目管理/代码架构…）。**关系——这是我们最重要的反面教材**:11 个场景 **100% 都是单用户对话**（连"代码架构设计"都硬塞成对话），只换 topic、ingest 形态零差异，且没有"如何加第 12 个场景"的说法。它把"场景"误解成"换个话题"，而非"换个（输入通道, 主体, 视角, 时间动力学）组合"——正是这个误解定义了我们的机会。

**第二代·状态机/可程序判分（和我们同源的机制）**
- **MEME**（2605.12477）:状态机 + state-diff（状态前后差分）出题，故意避开数值，考增改删/级联。**关系**:它和我们用的是**同一套状态机 + state-diff 机制**——这是我们机制撞 SOTA 的自我背书，但它仍是单一 benchmark、不跨场景。
- **Memora / FAMA**（2604.20006，**威胁最高的最近邻**）:个人助理对话 benchmark，用模拟器显式追踪记忆轨迹（Add/Update/Delete），提出**遗忘感知准确率 FAMA**（见 §2），考记忆/推理/推荐。**关系**:它的"状态机真值世界 + 增改删轨迹 + 显式遗忘"心智与我们高度同源，但它是**单场景（个人助理）、单媒介、LLM 当评委、一次性数据集**，并明确把多用户/社交关系列为 future work。**一句话:Memora ≈ 我们这台元工厂在"个人助理"这一个场景上的手工弱化实例**;我们借它的 FAMA 公式。

**第三代·评测器（evaluator，不是生成器）**
- **MemoryAgentBench**（2507.05257, ICLR'26）:把记忆评测归纳为 4 能力轴（精确检索 / 测试时学习 / 长程理解 / 选择性遗忘），并**重构现有数据集**来覆盖。**关系**:它是 evaluator（拿现成数据评系统）;**我们是它的上游 generator**（造数据）。
- **EvoMemBench / BEAM** 等同属此类:定义能力象限去评 15 种记忆方法。**关系同上**:它们让能力"可评"，我们让能力"可生成"。

**贯穿全版图的三条局限（= 我们的切入口）**:
1. **几乎全是固定数据集**:做一个用一次，新场景要从头再造一遍。
2. **人工标注贵**:LoCoMo 人工编辑、BEAM 人工校验、RealMem 手工设计场景。
3. **难跨场景 + 媒介单一**:绝大多数堆在"对话/单用户/第一人称"这一个角落（`scenario_dimensions.md` 的覆盖图证实）;非对话 ingest（会议/邮件/工单/代码）几乎无人覆盖。

## §2 评测/验证维度的分类：我们的"考什么 + 怎么判"从哪来

> 这是调研最厚的一条线（`survey/verifier_metrics/REPORT.md`，26 篇精读）。**核心发现**:遗忘有公认公式可借;冲突只有分类没有判分公式;巩固/归因**完全没有公式**——后两者正是我们造 verifier 的 novelty。
>
> 先解释一个贯穿全节的取舍:**verifier = 自动判分器**。判分有两条路——用代码确定性判（可证伪、零成本、无偏）vs 用一个 LLM 当裁判判（LLM-as-judge，灵活但有偏、贵）。**我们的立场是"代码 gt 优先、LLM-judge 只兜底"**，理由见 §2.5。

### 2.1 遗忘（forgetting）—— 启发我们的 L1.FORGET / L4 偏好线
- **TOFU**（2024）:用 200 个**虚构作者**（确保不在预训练里）测"模型能否真的忘掉指定知识"，提出 **Truth Ratio**（模型偏向旧值有多深的连续信号）。**关系**:它"用虚构数据绕开污染"的哲学 = 我们"造全新虚构世界防泄漏"的根据。
- **MUSE**（2024）:unlearning 6 维度（逐字记忆/知识/隐私/效用/可扩展/可持续）。**关系**:提醒我们测遗忘要同时盯"该留的有没有被误伤"。
- **FAMA**（Memora, 2026）:**遗忘感知记忆准确率** `FAMA = max(0, MPA − λ·(1−FAA))`——MPA = 该召回的召回率，FAA = 该排除的过时值排净率。**关系——直接搬**:把单一准确率拆成"该记的"和"该忘的"双分，比单准确率更能暴露"误用过时值"。接到我们的 FORGET / 偏好判分。

### 2.2 冲突（conflict）—— 启发我们的 L5 冲突可信线
- **Knowledge Conflicts Survey**（2024）:给出**三类冲突分类**（必抄）——CM（外部上下文 vs 模型自身知识）、IC（多个外部来源互相矛盾）、IM（模型自身前后不一致）。**关系**:我们把冲突类型显式编码进 schema。
- **WikiContradict / CounterFact**:真实矛盾段落对 / 21k 事实编辑对，作冲突语料 anchor。
- **关键空白**:这条线**只有"检测到没有"，没有"模型有没有正确处置冲突"的标准判分器**。**关系**:所以 L5 的 verifier 是我们自己造的——代码注入矛盾 + 写死裁决规则（如"信权威源"），gt = 规则输出（as-built `pipeline/lines/L5_conflict.py`，自检 20/20）。

### 2.3 巩固（consolidation）—— **完全空白，我们造，是 novelty 硬通货**
- **Rethinking Memory in LLM Agents**（2025）:提出记忆操作 6 分类，并**明说**"几乎没有标准化指标衡量巩固质量"——这就是我们卖点的官方背书。
- **LoCoMo / LongMemEval**:有"多会话推理"子任务，但**只测"答对没"，不测"是否真把多会话信息合并了"**。
- **关系**:巩固 verifier 没有任何现成公式，我们定义（correctness + 置信度随重复次数上升 + 抗噪），接到 L7 巩固/摘要线。**首个对记忆巩固直接评分的 verifier**。

### 2.4 归因（attribution）—— 启发我们的诊断层（存/取/用/忘四步）
- **AutoAIS**（2022）:用 NLI（自然语言推断，判断"A 是否蕴含 B"）模型自动判断"答案是否被引用来源支持"，与人评系统级相关 0.9+。**关系**:我们的归因 verifier 用 NLI 判"答案有没有真用上该记忆"。
- **Diagnosing Retrieval vs Utilization**（2026）:把 RAG 失败拆成"检索瓶颈 vs 利用瓶颈"。**关系——直接启发我们的诊断仪**:我们把记忆失败拆成 **写入→检索→利用→遗忘** 四阶，首个失败阶即归因（对应毕设 M1–M6 失败模式）。

### 2.5 LLM-as-judge 方法论 + 可验证奖励 —— 解释"我们为什么不用 LLM 判分"
- **MT-Bench**（2023）/ **G-Eval** / **Reference-Guided Verdict** / **JudgeBench**:这条线系统记录了 LLM 当裁判的三大偏见（位置偏好、长度偏好、自家模型偏好）和对策（多裁判投票 + 给参考答案 + 位置互换）。**关系**:即便我们偶尔不得不用 judge（如开放题），也照这套做;但它们恰恰证明 judge **难、贵、有偏**。
- **Tülu-3 / RLVR（可验证奖励, Reinforcement Learning with Verifiable Rewards）**（2024）:对能程序判分的任务（数学/代码），**直接写 verifier 函数返回 0/1，扔掉 LLM 裁判**。**关系——这是我们护城河的范式根据**:我们把"代码即真值"从数学/代码域**推广到任意记忆场景**——题型尽量约束到可程序判分（精确匹配/集合/数值/序相关 Kendall-τ），让答案预先算定、可证伪。
- **Phi-4 plurality voting**:多采样投票判难度（全一致=太易、全发散=太难、部分一致才留）。**关系**:接到我们的难度闸/质检闸。

> **小结（给学妹的导航）**:§2 这条线给了我们两样东西——【考什么】（遗忘/冲突/巩固/归因 → L1–L7 坐标）和【怎么判】（代码 gt 优先 + FAMA/Truth Ratio/NLI 公式 + judge 兜底的偏见对策）。**冲突与巩固没有现成判分器 = 我们造 verifier 的两块 novelty。**

## §3 数据合成 / 多智能体范式：我们的"中央议会"从哪来

> 来源 `survey/multiagent_synthesis/REPORT.md`（35 篇）+ `docs/anchors/research_multiagent_paradigms.md`。**反向生成（structure-first）+ 多智能体编织**是合成范式的两条主线。

- **DataMorgana**（2501.12789）:声明式、可配置正交类目→组合多样性的 RAG 问答生成器。**关系**:它开创"可配置正交维度控分布"，我们承其多样性思想;但它**类目人手写、单文档、无时间/无世界、gt 是 LLM 软标**——我们以代码 gt + 状态机世界补其空白。
- **AutoBencher**（ICLR'25）:把"难度/区分度"从事后体检升级成**出题时的优化目标 + 自适应搜索**。**关系**:我们的"中央办公室多轮迭代搜配置"借它。
- **APIGen-MT / ToolACE**（数据合成的 SOTA 模板）:**两相框架**——Phase1 先生成"蓝图"再过多裁判评审委员会，Phase2 再展开成交互轨迹。**关系——和我们 step1→step2 完全同构**:先出结构（白皮书）、过审、再展开语料。
- **CAMEL**（多智能体角色扮演圣经）:Inception Prompting（开场一次性注入角色，之后纯轮转）+ 5 大终止条件 + 4 大坑（角色漂移等）。**关系**:我们多智能体编织语料时照抄其避雷清单。
- **Persona Hub / Generative Agents / WizardLM(Evol-Instruct) / STaR**:角色枚举控多样性 / 仿真世界产 corpus / 演化算子控难度 / 失败回炉自举。**关系**:分别接我们的角色源、世界生成、难度旋钮、迭代闭环。

**但我们对多智能体有一个冷静的、被调研支撑的立场**（`research_multiagent_paradigms.md`，这点导师会关心）:
> **别为多智能体而多智能体。** 多篇复核（Stop Overvaluing MAD / More Agents Is All You Need）显示"多 agent 辩论"常打不过"强单 agent + 多采样投票"，且独立 agent 会**表征塌缩**（趋同到几乎一样）。真正的杠杆是 **① 角色异质性 ② 发散用并行、收敛用单一权威 ③ 把代码校验器当 critic 回灌**。

**→ 这正是我们"中央议会"的形态**:多个异质视角**并行发散**（提案），单一 architect **收敛成一个自洽世界**（绝不投票），再用**代码校验器**（单调性/矛盾/引用完整性）定向回灌精修。落地用 LangGraph（有向状态图 + checkpointer，可审计、可复现、可 resume），而非自由对话框架。

## §4 规格澄清（spec refinement）：我们"白皮书=被执行的合同"从哪来

> 来源 `survey/spec_refinement/`（8 篇论文 + 5 家 deep-research 产品博客）。"规格澄清"= 用户需求模糊时，系统**先问清/先定规格再动手**。

- **CLAM / ClarQ-LLM / Ask-or-Assume / First-Ask-Then-Answer / STaR-GATE / Tree-of-Clarifications (ToC)**:这批论文研究"模型何时该反问澄清、怎么生成澄清问题、怎么把答复重写成规格"。
- **5 家 deep-research 产品的 clarify 范式对照**（很有用的工程经验）:
  - LangGraph `open_deep_research`:**显式 `clarify_with_user` 节点**（Pydantic 强约束三字段:要不要问/问什么/确认开工）——最干净可复用。
  - OpenAI:三角色 handoff（Triage→Clarifier→Instruction Rewriter）。
  - Gemini:**plan-first**——不追问，直接生成 plan 给用户**编辑**（对专家用户友好）。
  - Anthropic / Perplexity:**隐式澄清**（orchestrator 自己决定 / 对自己问）——**不可审计**。

**和我们的关系**:我们的输入是"场景描述 + few-shot"，而**关键信息（评测视角、记忆主体、时间跨度）用户脑子里有但没说出来，搜也搜不出来**——所以隐式澄清是死症，**我们必须显式澄清**。这条线落到我们的**"白皮书"机制**:中央议会把模糊的场景描述，澄清并固化成一份**结构化白皮书**（激活哪些产线、各产线配比、共享世界 schema、输出媒介），这份白皮书**不是自由文本 brief，而是一份被下游代码逐字执行的"合同"**——既是规格澄清的产物，又是整条流水线的驱动指令。

## §5 ★我们的定位（最重要）：我们填了哪个空白

### 5.1 一句话
> 上述所有工作，要么是**一个固定数据集**（LoCoMo/LongMemEval/RealMem/Memora…），要么是**一个评测器**（MemoryAgentBench/BEAM…），要么是**别的域的生成器**（DataMorgana 做 RAG QA、AutoBencher 不懂记忆）。**没有任何一个同时做到:【记忆 benchmark 的生成器】×【代码可证伪的 gt】×【场景自适应】。这个三交集就是我们的空白。**

### 5.2 三件区别于所有人的事

**① 我们是【生成器 / 元工厂】，不是【数据集】。**
- 架构 = **宪法 → 中央议会 → 多产线 → 场景化媒介**（科层官僚隐喻，`redesign_factory_v2.md`）:
  - **宪法**（人写死）= 记忆能力坐标系 **L1–L7**（时间线 / 关系多跳 / 过程序列 / 隐式偏好 / 冲突可信 / 边界拒答 / 巩固摘要），每条 = 一类记忆挑战 + 一种代码 gt 基质。
  - **中央议会**（多轮 agentic）= 读"场景+few-shot"产出**白皮书**（§4）;**区分度在此被设计**——不同场景激活不同产线组合。
  - **多产线**（并行 agent + 代码）= 每条产线读同一个**共享世界**的不同切面，各自带代码 gt。
  - **场景化媒介**= 把同一个世界渲染成会议/邮件/周报/对话/交易流等不同外壳。
- **对比**:RealMem 手工 11 个、Memora 手工 1 个;我们喂场景描述就现造，人不碰 prompt。

**② 代码可证伪的 gt（护城河）——LLM 全程不碰答案。**
- 把"标准答案怎么来"从最依赖 LLM 到最可证伪排开（`related_work.md` 的 gt 谱系）:
  `LLM写答+LLM判（DataMorgana）→ LLM合成+人工/judge（LifeDialBench）→ agent自洽+judge（AgentFrontier）→ 模拟器trace+代码准则（Memora，trace 仍是 LLM 产物）→ 代码执行过滤（InfoSynth，仅纯代码域）→ 【我们】状态机机械切片，预先算定`
- **只有我们做到"从一个独立状态机机械切片、答案预先算定，LLM 只负责把世界渲染成好看的语料、绝不碰答案"。** 判分用精确匹配/集合/数值/Kendall-τ 等代码确定性手段（RLVR 哲学从数学/代码推广到记忆）;冲突/巩固这两块无现成公式的，我们造 verifier。
- **理论加成**:可证明的"训评正交"——信号事实在语料里只渲染一次、答题须跨多个变更周组合，故训练样本对评测题在支撑集意义上**实例级不可达**（比 ProDa 的事后启发式隔离强一个层级）。

**③ 端到端 + 盲审闭环 + 诊断仪。**
- 每题带双标签:**L1–L7（考什么记忆）× 𝓕𝓔𝓠 算子 × M1–M6 失败模式（会怎么错）**（毕设 taxonomy），所以产出的不只是分数，而是"谁缺哪种能力"的诊断。
- **盲审/防泄漏闸**:mention-on-change（每个事实只在发生那一刻出现一次）+ 硬判别器（无语料/单证据 baseline 能答中就丢）+ 反相似度污染自检 + 真系统×多场景跑**排名翻转**实验来证明区分度。

### 5.3 给导师的收尾话术
> **现有记忆评测，是一张张为特定场景手画的考卷;我们做的是一台印考卷的机器——你给它一个新场景，它现场出一整套题，而且每道题的标准答案是用代码从一个独立的"事实世界"里机械算出来的，出题的 LLM 自己都不知道答案。这让评测第一次可以"按需生成、跨场景泛化、且答案可证伪"。我们填的，就是"记忆 benchmark 生成器 × 代码 gt × 场景自适应"这个此前没人占住的三交集。**
