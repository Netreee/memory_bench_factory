# 补丁体检 —— 域无关 pipeline 里残留的写死域值(算法债)

> **缘起**:工程 session 做的一次"补丁体检"——扫全仓(`config.py` + `pipeline/` + `tools/`,~3100 行 live 代码),找"为某次实验突兀打的硬补丁"(代码 / 规则 / prompt)。
> **结论先行**:**仓库整体有原则、不是补丁堆**。但有一簇真补丁,**根因同一个:号称"域无关"的 pipeline 里仍残留写死的域知识/域值**。
> **为什么是算法工作**:这是 §S"白皮书算了没执行"的**镜像**——那边"该执行的目标没执行",这边"**该从白皮书/世界派生的域值,代码里写死了**"。两者合起来才是完整的"域无关化"债。

---

| 类别 | 数量 | 处置 |
|---|---|---|
| **写死域值的代码补丁** | 2(★该修) | 根因修复:从 `field_schema.kind` / 世界派生 |

| 魔法数字 | 若干 | 轻微;几个该改成白皮书可配 |

## §1 这些【不是】补丁(有原则的鲁棒性,该留 —— 别"清理"掉承重的)
- `httpx` 分段超时 + `chat_json` 退避重试 + **全局并发信号量**(根治了僵尸 socket / API 抽风);
- `_as_int` 稳健强转(根治 LLM 把 session 写成字符串导致 `max()`/排序崩);
- `json_repair` + 抓第一个 `{}`/`[]` 容错(治 reasoning 模型 JSON 手滑);
- 接地闸 §G、各线 `gt()` 校验闸、多样性 `try/except` 失败安全、并发下丢空题面。

→ 这些都是**根因修复**(定位到病灶、一次治本),不是日抛补丁。

## §3 统一根因(算法层)
**一簇真补丁(★1 ★2 + 规则 3)指向同一件事:pipeline 自称"域无关",但仍把【域知识/域值】写死在代码/prompt 里**——人名靠中文子串猜、职级写死成 CTO/CEO、禁词写死成中文。

这是 §S 那条主线的**另一半**:
- §S(白皮书 → 执行):议会**算了**目标(weight/规模/难度),执行端**不读** → "该执行的没执行"。
- 本审计(代码 → 白皮书):该从白皮书 `field_schema.kind` / 世界派生的域值,代码里**写死了** → "该派生的没派生"。

→ 合起来才是完整的**域无关化**:**所有域知识只有一个来源(白皮书/世界),代码与 prompt 不得私藏域值**。

---

## §4 建议处置
- **★1 立即可做(干净根因修复)**:`_tracked_blocklist(ws, profile)` 改读 `kind=="person"` 字段名 → 取其值入屏蔽表,删掉 `hints` 子串启发式。顺带堵 medical 的不可靠点。**纯工程、零行为风险(office 行为不变、medical 变可靠)**。
- **★2 稍深(算法+工程)**:L2 下一跳值的来源——要么世界生成阶段造好这一跳(接 §W),要么从 profile 派生角色词表。先记此,与"L2 基质从哪来"一起议。
- **3/4/5 可接受**:保留,但在各处加一行"此为反应式/域相关规则,不跨语言/域"的标注;难度/W.3 上结构化代码闸后,部分 prompt 禁求可退役。
- **魔法数字**:把 `max_n / max_per_path / 重渲次数` 等接进白皮书可配(§S 目标驱动时一并做)。

> **一句话**:没烂,真正扎眼的就 ★1 ★2 两处写死域值;它们和"域无关"招牌冲突,且 ★1 顺带是 medical 的可靠性洞。修法统一 = **域值只从白皮书/世界来,代码不私藏**。
