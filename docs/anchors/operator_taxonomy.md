# 𝓕-𝓔-𝓠 三元算子:记忆系统操作分类

> **来源**:任子谦《大模型记忆系统评测基准研究》(SJTU 学士学位论文,2026-05-13) 第 3.3.1 节。
> **用途**:我们 benchmark 生成 pipeline 的【题目签发标签骨架】——每道题预先标注它考的是哪个算子层,使下游评测能直接定位到具体的 (𝓕, 𝓔, 𝓠) cell。

---

## 1. WMR 闭环

毕设把智能体记忆系统形式化为 **𝒜 = ⟨𝓛, 𝓜, 𝓡⟩**(语言模型、记忆架构、推理范式)。
其中 𝓜 在每个时间步 t 按 Write-Manage-Read 闭环运行:

```
e_t      = 𝓡(𝓜_t, x_t)              # 读取阶段:根据查询召回证据
a_t      = π_𝓛(x_t, e_t, g_t)        # 生成阶段:基于证据与目标产出答案
𝓜_{t+1}  = 𝓤(𝓜_t, x_t, a_t, o_t)    # 写入/更新阶段:本轮经验沉淀回记忆
```

对应 Du 综述 (arXiv 2603.07670) 的 "Write — Manage — Read" 三元闭环。

## 2. M 轴形态(粗粒度)

| 类别 | 定义 | 检索机制 | 实例化系统 |
|---|---|---|---|
| **𝓜_Flat**(扁平 1D) | 记忆单元为按时间追加的离散文本块,无显式实体关系 | 向量近邻 + 可选重排 | simpleMem, Mem0, MemGPT |
| **𝓜_Planar**(关联 2D) | 引入图或表结构,显式建模实体—关系—时序 | 图遍历(PPR/子图扩展)+ 向量近邻混合 | mem0^g, HippoRAG, A-MEM, MIRIX |
| **𝓜_Hier**(分层 3D) | 通过递归摘要建立"全局—局部"多层索引 | 层级遍历或 collapsed-tree 聚合 | RAPTOR, MemOS |

## 3. 𝓕 构造算子(Formation):原始上下文如何被转化为可检索的记忆单元

| 级别 | 名称 | 定义 |
|---|---|---|
| **F1** | 切片 | 文本切成 chunk,存为向量或文本块 |
| **F2** | 原子事实抽取 | LLM 抽取候选事实(`(entity, attribute, value)` 三元组简化) |
| **F3** | 实体—关系三元组抽取 | 在 F2 基础上显式区分实体节点与关系边 |
| **F4** | 多层异构结构 | F3 之上引入聚类摘要、社区分割或多层级树,兼具"全局—局部"两类粒度 |

## 4. 𝓔 演化算子(Evolution):新数据进入时如何更新已有记忆

| 级别 | 名称 | 关键策略 |
|---|---|---|
| **E1** | 只增不减 | 直接追加,冲突由检索时间戳过滤或并存策略处理 |
| **E2** | 缓存置换 | 类似 OS 的 LRU/FIFO 调度,或基于重要性/热度评分 |
| **E3** | 拓扑融合 | 节点合并(Entity Resolution),或为已有图增加新边、修改拓扑 |
| **E4** | 显式修补 | 检测到事实冲突后,执行覆盖式更新或记录显式 Edit Path 以保留版本可追溯 |

## 5. 𝓠 检索算子(Querying):查询如何召回证据

| 级别 | 名称 | 定义 |
|---|---|---|
| **Q1** | 相似度 | dense/sparse retrieval(embedding 或 BM25) |
| **Q2** | 游走/遍历 | 图上 PPR/BFS,或摘要树上从根向下遍历 |
| **Q3** | 生成/路由 | 先用 LLM 生成"中间变量"(查询重写、子问题分解、Clue/SQL),再用该中间变量去查 |

## 6. R 轴推理范式

| 级别 | 名称 | 控制流伪代码 | 现代代表 |
|---|---|---|---|
| **R1** | 直接检索 | `e ← M.retrieve(x); y ← L(x, e)` | 标准 RAG |
| **R2** | 迭代式检索 | 循环 `{e_k ← M.retrieve(q_k); y_k ← L(q_k, e_k); s_k ← L.critic(y_k, e_k); 若 s_k > τ 返回,否则 q_{k+1} ← L.rewrite(x, e_k, y_k)}` | Auto-RAG, Self-RAG |
| **R3** | 计划式 | `P ← L.plan(x); 对每步 i, e_i ← M.retrieve(P_i); 动态 P ← L.replan(P, e_i); 最终 y ← L.summarize(∪_i e_i)` | PlanRAG, Plan-and-Solve |

## 8. 关键观察(毕设第 6 章工业含义)

### 观察 A:CR 任务上 𝓕 的跃迁分水岭(F2 → F3 / F4 的质变)

仅做向量切片或事实抽取后写入扁平存储 (F1/F2) 的系统在 CR 上 R3 普遍偏低:
- simpleMem 10.1% · MemGPT 4.6% · MIRIX 3.8% · Mem0 3.7% · A-MEM 0.9% — 全部 ≤ 10%

引入显式实体—关系结构 (F3) 或多层异构摘要 (F4) 后,CR R3 跃升至 25–52%:
- HippoRAG 25.8% · mem0^g 52.1% (F3) · MemOS 29.9% · RAPTOR 47.0% (F4)

**HippoRAG vs RAPTOR 对照**(二者 𝓔=E1 + 𝓠=Q2 一致,仅 𝓕 不同):**CR R3 相差 21.2 pp**——F3 与 F4 的边界就是质变临界。

### 观察 B:演化算子需要"复合性"才能激活 R3 反思

**mem0^g vs HippoRAG**:9 系统中唯一一组 "𝓕 与 𝓠 同标签、𝓔 不同" 的对照:
- HippoRAG (F3+**E1**+Q2):CR R1 → R3 = 30.1% → 25.8%,**ΔR3 = -4.3 pp**
- mem0^g (F3+**E3+E4**+Q2):CR R1 → R3 = 35.2% → 52.1%,**ΔR3 = +17.0 pp**
- **ΔR3 相差 21.3 pp**

**对照 Mem0** (F2+E4+Q1):CR R3 仅 3.7%,ΔR3 ≈ 0。

**工程含义**:E4 单独存在并不足以激活 R3 反思,**需要 E3 拓扑融合 + Q2 图遍历召回路径同时具备**,才能把 R3 的多步反思转化为对当前有效版本的判断。

### 观察 C:题型 × 形态的交互(R3 协同方向不一致)

mem0^g (F3+Q2) 在 MAB 四子任务的题目级题型分解显示 R3 协同方向取决于题型:
| 题型类别 | n_R1 / n_R3 | ΔR3 (mem0^g) | ΔR3 (simpleMem) | ΔR3 (RAPTOR) |
|---|---|---|---|---|
| single-hop | 1160 / 1137 | **+12.1 pp** | ≤ 7 pp | [0, +8] pp |
| multi-hop | 186 / 171 | **+12.7 pp** | ≤ 7 pp | [0, +8] pp |
| state-tracking | 95 | **-25.5 pp** | ≤ 7 pp | [0, +8] pp |
| aggregation | 17 | **-30.5 pp** | ≤ 7 pp | [0, +8] pp |

simpleMem (F1+Q1) 跨 5 类题型 R 升级钝感;RAPTOR (F4+Q2) 跨 5 类题型小幅正向。

### 观察 D:Q3 路由的 token 代价

生成路由型检索 (Q3) 每次检索附带一次 LLM 路由调用,单题 token 用量比 Q1 / Q2 高一个数量级。CR 任务上 MIRIX (Q3+R3) 相对 RAPTOR (Q2+R2) 的 token 代价高出一个数量级但准确率不占优。

**Q3 + R3 复合组合**在 token 预算受限场景下不是首选;**Q1/Q2 + 适度 R 升级**(如 mem0^g R3 或 RAPTOR R2)仍位于 Pareto 前沿。

## 9. 适配器接口(毕设第 3.5 节,我们生成的 benchmark 必须兼容)

```python
class MemoryInterface:
    def ingest(self, document: str, metadata: dict) -> None:
        """将一段文本写入记忆,metadata 至少包含 timestamp 与 source。"""

    def retrieve(self, query: str, top_k: int = 10) -> List[Evidence]:
        """根据查询返回若干证据,每条证据包含 content / source_id / score。"""

    def update(self, memory_id: str, new_content: str) -> None:
        """可选:对已有记忆执行覆盖式更新(仅 Mem0/Zep/A-MEM 等具备此能力的系统实现)。"""

    def reset(self) -> None:
        """清空记忆体(在 instance 切换时使用)。"""
```

## 10. 对我们 Pipeline 的具体启示

**核心用法**:每道题预先打 `(𝓕_op, 𝓔_op, 𝓠_op)` 三元算子标签 + `task_type` (AR/CR/TTL/LR) 标签,作为生成时的【签发标签】。下游 evaluator 可以直接定位"这道题考的是哪个算子层"。

**生成策略**:
- **测 E4 显式修补**:出"用户先说住北京,后说住上海(且有触发事件)"这种带版本的 update 链题。E1 系统的检索会同时返回两条只能靠时间戳;E3+E4 系统能显式 mark outdated 并归并版本。
- **测 Q2 图遍历**:出"两跳推理"题,要求把 A→B、B→C 这两个三元组串起来。Q1 系统拼接两次相似度检索准确率会显著低于 Q2 系统。
- **测 F3 三元组抽取**:出"必须明确知道 (entity, relation, entity) 才能答"的题。F1 切片粗粒度会丢关系。
- **测 F4 分层摘要**:出"既需要细节又需要全局"的题(如"过去 10 周整体节奏 vs 第 7 周具体阻塞")。
- **测 E3 拓扑融合**:出"同一实体不同表述需合并"的题(如"P0/P1 缺陷 vs 高优先级缺陷")。
