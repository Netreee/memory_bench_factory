# 四条线踩坑总结 —— 按盲审波次的【问责账】

> 用途:① 论文"挑战与教训"底稿;② 后续线避坑清单。
> ★本文按【盲审波次】组织(不是抽象主题):**每波审出什么 → 我怎么解 → 下一波证明奏效没**。
> 这是诚实账:很多"修好了"的 bug 下一波原样复发;只有最后一版才真死。把这个过程记下来,比记结论值钱。

## 2. ★我自己也打了补丁(独立审计当场点名)
`audit_blindfix_run210907.md`(只看代码不信注释)给我的 Fix1/2/3 判:**主体根因式(7/10),但夹 1 处真补丁**:

## 3. 从这 5 波里抽出的真教训(都带实证,不是空话)

1. **★自检全绿 ≠ bug 死了。** 每次 fix 自检都绿,下一波照样复发——因为自检没覆盖**真实消费者路径**(评审导出读 `gt.session`、LLM phraser 会改写、`numeric` vs `number` 词表)。→ **fix 的"完成"判据是【下一波独立盲审确认】,不是【自检绿】。** 关键路径必须拿**真实产物**抽验(我直到 020444 才去 grep `reviewed_qa.json`,才看见导出读的是 session)。

2. **★我一补再漏的根:每次修在【我以为的出错点】(某个 render 站点),但真实消费者读【另一个字段】。** 补题面漏 gold、补 cue 漏 LLM、加 week 漏并存的 session。→ 正解不是追着消费者补,而是**让 gold 本身无歧义**(删掉可被误读的内部字段),从源头消除选择。

3. **接地存活率单调涨到 100%、综合分却不动。** 单一硬指标会骗人;边B闸把"值在不在语料"刷满,管不到周号/类型/多跳/多样性。→ **必须多边、多视角交叉**,别信一个涨满的数。

4. **"看着像不变量" ≠ "是不变量"。** roles_of(13%误杀/0覆盖)、W5(10%/0)、INV-5(16/16误杀)——形式全合格(查世界、无字面量),全是症状相关代理。这几个是**我自己用真实数据量 FP/覆盖率**才毙掉的(少数自查成功的)。→ 闸条上线前必过实测关。

5. **闸是事后兜底,源头修复才是主力。** 补 render 站点是补丁;改 gold 烘焙 / enumerate 跳复现 / world 去近重名 / inject 排己,才让闸退回防回归(新鲜 order ≈0 触发)。

6. **type-critical 表面别交给 LLM 自由发挥。** 给了正确 cue("是多少")phraser 还能写"是谁"——疑问词/周号/答案类型要模板或铁律锁死。

7. **难度件可能反噬良定义**(近重名陷阱本意考消歧、实际造坏题);**域知识只从白皮书**(写死 CTO/CEO、中文子串猜字段都翻过车)。

---

## 4. 一页纸结论(给 L4/L6/L7)
- **fix 不算完,直到下一波独立审确认**;关键路径拿真实产物抽验,别只信手搓夹具。
- **让 gold 出厂即唯一人类口径**(无裸 session/无内部词表),从源头消歧,别追消费者补。
- **闸条必过实测 FP/覆盖**;反补丁靠独立审计,不自评。
- **先把源头(prepare/enumerate/gt)做对**,闸只兜底。
- 单指标会骗人 → 多边交叉;type-critical 表面别交给 LLM;难度件先过良定义;域知识只从白皮书。
