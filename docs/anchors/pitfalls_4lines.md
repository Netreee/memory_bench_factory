# 四条线(L1/L2/L3/L5)踩坑总结 —— benchmark 生成器的"什么使造题难"

> 用途:① 论文"挑战与教训"一节的底稿;② 后续产线(L4/L6/L7)的【避坑清单】。
> 按【根主题】组织(非时间线),每条 = 症状 → 根因 → 教训/原则。

---

## 0. 统领:验证三角是地基
一道好题 = (**题面 question / 答案 gold / 语料 corpus**)三者一致,且同源于唯一世界:
- **边 B 接地**(gold↔语料):gold 能否在语料逐字+就近找到。`grounding.py`,渲染后。
- **边 A 良定义**(题面↔答案):gold 是该题面在世界里的唯一正确解。`well_posed`,出题前。
- **边 C 可答性**(题面↔语料):只读语料能否答出。reader-based,多数尚未建。

三边正交、各需一道闸;任何一边松动都出坏题。**所有坑都能归到"某条边没守住"。**

---

## 1. ★最大教训:接地存活率 ≠ 正确率 ≠ 多样性
- **症状**:run020444 规模翻 4 倍、接地存活刷到 **100%**,盲审综合分却【不升反微降】。
- **根因**:边 B 闸只保证"值在语料里",**完全管不到** 周号/类型/多跳末跳/题型多样性这些边 A / 边 C / 渲染层的病。
- **教训**:**任何单一硬指标(存活率/规模/字数)都会给"变好"的错觉。** 必须多边、多视角(独立盲审 + 程序化多样性)交叉,别被一个涨满的指标骗。

## 2. ★出题段根因:gold 必须"出厂即唯一人类口径"
- **症状**:off-by-one **5 连发**——明明加了 `week_label`,周号还是差 1。
- **根因**:gold 在 **orders 阶段用机器内部表示**烘焙(0-based session、内部 `kind` 词表),这些内部表示**漏进 shipped gold**;下游(评审导出/评分/LLM 渲染器)各自挑字段、各自渲染 → 同一事实在三处表面**漂移**。例:TR gold 同时有 `session:4`(0based)和 `week:5`(1based),导出挑了 session。
- **教训**:**gold 出厂即是【唯一的、人类口径的、无歧义的】表示**——不 ship 任何"内部 0-based / 内部词表"让下游去挑或改。命门1(单一真源)要从"共享值"扩到"共享表面"。

## 3. ★"看着像不变量" ≠ "是不变量"(反补丁的硬标准)
- **症状**:三个闸条被实测毙掉——`roles_of`(L2 桥唯一,**13% 误杀/0 真覆盖**)、`W5`(L1 MR平手,**10%/0**)、`INV-5`(L2 起点自带末跳字段,**16/16 全误杀**)。
- **根因**:它们形式上全合格(查世界、不含字面量),但量的是**症状相关量**(连接度/平手/同名字段)而非**歧义本身**——与"答案是否唯一"正交。
- **教训**:"查世界 + 不含字面量"只是**必要非充分**。一条闸条必须再过实测关:**它 drop 的确为坏题(真覆盖>0)+ 不误杀好题(FP≈0)**。拿真实世界数据量 FP/覆盖率,别凭"形式像"就收。

## 4. ★闸是事后兜底,源头修复才是主力
- **症状**:补 render 站点(intent 的 week_label / interrogative)一补再漏——补了题面漏了 gold、补了 cue 漏了 LLM 覆盖。
- **根因**:闸在【产物末端】,治不了【源头产坏题】;补单个 render 站点是补丁,下个没补的站点照漏。
- **教训**:**先让源头不产坏题**(L3 enumerate 跳复现值 / L5 inject 排己别周真值 / world_gen 去近重名 / gold 烘焙即规范),闸退回它该有的角色 = **廉价兜底 + 防回归**(新鲜 order 上应≈0 触发)。

## 5. LLM 渲染器有自由度,type-critical 表面要锁死
- **症状**:intent 给了正确 cue("Oncall 是多少"),phrase LLM 还是写成"Oncall 是谁"。
- **根因**:phrase 是自由生成的 LLM,会无视/覆盖语义提示。
- **教训**:**凡影响"答案对不对"的表面(疑问词/周号/答案类型),不能交给 LLM 自由发挥**——要么模板填空、要么 prompt 立铁律(④ 保留疑问类型),并接受"仍可能漏 → 需 reader-based 边C闸兜"。

## 6. 自检 fixture 必须对齐真实 schema
- **症状**:`field_kind` 词表写 `number`,而白皮书 `field_schema` 实际是 `numeric` → numeric 落到"是什么";**自检 fixture 也用了 `number`,所以假绿,放过真 bug**。
- **教训**:**测试夹具用错词表 = 假绿,比没测更危险**。fixture 必须取自真实产物/schema 的同一词表;关键路径的自检要用真实 run 的 order 抽验,不只手搓夹具。

## 7. 引入"难度/陷阱"可能反噬良定义
- **症状**:白皮书 traps 的"近重名实体"陷阱 → world 生成 张三/张三(数据)/张三_数据 → 渲染塌缩成裸"张三" → 题目无唯一指代(ill-posed)。本意考消歧,实际制造坏题。
- **教训**:**难度件必须先过良定义**。要么撤(做不到全程消歧渲染),要么做成专门、严格控渲的能力线;别让它泄进所有线。新难度先问:它会不会破坏唯一解?

## 8. 域无关化:域知识只从白皮书来
- **症状**:写死下一跳=CTO/CEO 角色(★2 别名漂移)、用"负责/汇报"中文子串猜人名字段(★1,对 medical 失效)。
- **教训**:**产线代码/prompt 不许夹域知识**;实体名、人名字段、体裁、停用语等一律从白皮书 `domain_profile` 取。判据:换 medical 场景还成立吗?

---

## 一页纸结论(给后续线)
1. 新线的 gold **出厂即唯一人类口径**(周→week_label、答案类型显式、无裸 session)。
2. 新线的 well_posed 闸条**必须实测 FP/覆盖**,别上"形式像"的代理。
3. **先把源头(prepare/enumerate/gt)做对**,闸只兜底。
4. type-critical 表面**别交给 LLM 自由发挥**。
5. 自检**对齐真实 schema 词表** + 真实 order 抽验。
6. 难度件**先过良定义**,域知识**只从白皮书**。
