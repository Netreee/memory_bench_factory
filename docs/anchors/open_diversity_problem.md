# 待解:多样性问题(★重要,未拍板做法)

> 状态:**问题确认、根方向有假设、做法未定**。记下来防遗忘;不急着实现(主理人:别上 prompt 词库补丁)。

## 问题(run020444 盲审 C 视角,程序化实测)
- **不是字面雷同**:剥数字后 280 万对文档,近重复对 = 0(没有"换数字整篇灌水")。
- **是两层语义单薄**:
  1. **题型集中**:汇报对象+排序占 **74%**,考点扎堆 4 个指标。
  2. **话题集中 + 文档内注水**:12 个主题吃 95% 文档;38% 文档把一个数字重复 ≥5 次;AI 套话高频(高效/协同/坚实…)。
- IDO 指标退步(0.14→0.38→0.56)的真因 = 话题集中 + 套话样板,**非草堆复制**。

## 为什么【不能】走"渲染 prompt 砍套话/限数字"这条路(主理人的判断,认同)
- **维护一个 prompt 词库不现实**:套话词、注水模式因场景而异;office 的"赋能/闭环"换到 medical 就是另一套。**词库无法跨场景泛化** = 又一个域相关补丁(违反"域知识只从白皮书 + 反打地鼠")。
- prompt 层只能压"症状"(某些词),压不住"世界本身就单薄"这个根。

## 根方向假设:从【世界生成】动手(待验证,非定论)
多样性的根可能在**世界太单薄** → 渲染再努力也只能在贫瘠世界上翻来覆去:
- **题型集中** ← 世界结构单一(都是"部门×指标×负责人"几种字段)→ 可产的能力/考点就那几种。**根治可能在:世界生成出更丰富的实体类型/字段类型/关系类型**(让 L1–L7 各有充足且多样的着床点),而非出题端事后打散。
- **话题/套话集中** ← 世界事件本身重复(每周都是"P0率/Oncall/SLA"循环)+ 渲染没有可写的新东西 → 只能堆套话填字数。**根治可能在:世界带更丰富的事件/字段语义**,让每篇文档有真东西可写,filler 才不靠套话。
- 配套(出题端,确定要做的小件):闭环配额加 **per-capability / per-field 上限**(强制打散考点)——这个是旋钮的自然延伸,和"世界更丰富"是两层、可并行。
